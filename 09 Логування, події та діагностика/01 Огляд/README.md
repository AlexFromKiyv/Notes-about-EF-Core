# Огляд логування, події та діагностика. 

Entity Framework Core (EF Core) містить кілька механізмів для створення журналів, реагування на події та отримання діагностичних даних. Кожен з них адаптований до різних ситуацій, і важливо вибрати найкращий механізм для поточного завдання, навіть якщо може працювати кілька механізмів. Наприклад, для ведення журналу SQL можна використовувати перехоплювач бази даних, але це краще обробляється одним із механізмів, спеціально розроблених для ведення журналу. На цій сторінці представлено огляд кожного з цих механізмів та описано, коли кожен з них слід використовувати.

## Короткий довідник

У наведеній нижче таблиці міститься короткий огляд відмінностей між описаними тут механізмами.

|Механізм|Async|Сфера застосування|Зареєстровано|Цільове використання|
|--------|-----|------------------|-------------|--------------------|
|Просте логування|No|За контекстом|Конфігурація контексту|Ведення логів під час розробки|
|Microsoft.Extensions.Logging|No|За контекстом*|Конфігурація D.I. або контексту|Виробниче логування|
|Події|No|За контекстом|Будь-коли|Реагування на події EF|
|Перехоплювачі|Yes|За контекстом|Конфігурація контексту|Маніпулювання операціями EF|
|Слухачі діагностики|No|Процес|Глобально|Діагностика застосунку|

* Зазвичай Microsoft.Extensions.Logging налаштовується на рівні всього застосунку за допомогою механізму впровадження залежностей (dependency injection). Однак на рівні EF для кожного контексту, за потреби, можна налаштувати окремий реєстратор (логер).

## Просте ведення логів

До логів EF Core можна отримати доступ із будь-якого типу застосунку, скориставшись методом LogTo під час налаштування екземпляра DbContext. Зазвичай це налаштування виконується в перевизначеному методі DbContext.OnConfiguring. Наприклад:

```cs
protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
    => optionsBuilder.LogTo(Console.WriteLine);
```
Додаткову інформацію див. у розділі «Просте логування».

## Microsoft.Extensions.Logging

Microsoft.Extensions.Logging — це розширюваний механізм логування, що підтримує підключані провайдери для багатьох поширених систем логування. EF Core повністю інтегрується з Microsoft.Extensions.Logging, і саме цей механізм ведення логів використовується за замовчуванням у програмах ASP.NET Core.

Докладнішу інформацію див. у розділі «Використання Microsoft.Extensions.Logging в EF Core».

## Події

EF Core надає події .NET, які слугують зворотними викликами (callback-функціями) у разі виникнення певних подій у коді EF Core. Події простіші за перехоплювачі й дозволяють гнучкішу реєстрацію. Однак вони є суто синхронними, тому не можуть виконувати неблокувальні асинхронні операції введення-виведення.

Події реєструються для кожного екземпляра DbContext, причому цю реєстрацію можна виконати в будь-який момент. Використовуйте діагностичний слухач (diagnostic listener), щоб отримати ту саму інформацію, але для всіх екземплярів DbContext у межах процесу. Докладніші відомості див. у розділі «Події .NET в EF Core».

## Перехоплення

Перехоплювачі (інтерцептори) в EF Core дозволяють перехоплювати, змінювати та/або пригнічувати операції EF Core. Сюди входять як низькорівневі операції з базою даних (наприклад, виконання команди), так і операції вищого рівня (наприклад, виклики SaveChanges).

Перехоплювачі (interceptors) відрізняються від логування та діагностики тим, що вони дозволяють змінювати або скасовувати операцію, яка перехоплюється. Для ведення логів краще використовувати просте логування або Microsoft.Extensions.Logging.

Перехоплювачі реєструються для кожного екземпляра DbContext під час налаштування контексту. Використовуйте діагностичний слухач (diagnostic listener), щоб отримати ту саму інформацію, але для всіх екземплярів DbContext у межах процесу.

Див. розділ «Перехоплення» для отримання додаткової інформації.

## Діагностичні слухачі

Діагностичні слухачі дозволяють відстежувати будь-яку подію EF Core, що відбувається в поточному процесі .NET. Діагностичні слухачі (diagnostic listeners) не підходять для отримання подій від окремого екземпляра DbContext. Перехоплювачі (interceptors) в EF Core надають доступ до тих самих подій, дозволяючи виконувати реєстрацію для кожного контексту окремо.

Діагностичні слухачі (diagnostic listeners) не призначені для ведення логів. Для ведення логів краще використовувати просте логування або Microsoft.Extensions.Logging.
