# Як працюють запити

Entity Framework Core використовує Language Integrated Query (LINQ) для запиту даних з бази даних. LINQ дозволяє використовувати C# (або вашу обрану мову .NET) для написання строго типізованих запитів на основі похідного контексту та класів сутностей.

## Життя запиту

Наведений нижче опис є загальним оглядом процесу, через який проходить кожен запит.

1. Запит LINQ обробляється Entity Framework Core для створення представлення, готового до обробки постачальником бази даних.
    a. Результат кешується, щоб цю обробку не потрібно було виконувати щоразу, коли виконується запит.

2. Результат передається постачальнику бази даних
    a. Постачальник бази даних визначає, які частини запиту можна обчислити в базі даних.
    b. Ці частини запиту перетворюються на мову запитів, специфічну для бази даних (наприклад, SQL для реляційної бази даних).
    c. Запит надсилається до бази даних, і повертається набір результатів (результати – це значення з бази даних, а не екземпляри сутностей)

3. Для кожного елемента в результуючому наборі
    a. Якщо запит є запитом відстеження, EF перевіряє, чи дані представляють сутність, яка вже знаходиться в системі відстеження змін для екземпляра контексту.
        * Якщо так, повертається існуюча сутність
        * Якщо ні, створюється нова сутність, налаштовується відстеження змін і повертається нова сутність.
    b. Якщо запит не потребує відстеження, то завжди створюється та повертається нова сутність.

## Коли виконуються запити

Коли ви викликаєте оператори LINQ, ви просто створюєте представлення запиту в пам'яті. Запит надсилається до бази даних лише після використання результатів. Найпоширеніші операції, які призводять до надсилання запиту до бази даних:
    * Ітерація результатів у циклі for, foreach
    * Використання оператора, такого як ToList, ToArray, Single, Count або еквівалентних асинхронних перевантажень

Попередження

Завжди перевіряйте введені користувачем дані: Хоча EF Core захищає від атак SQL-ін'єкцій, використовуючи параметри та екрановані літерали в запитах, він не перевіряє введені дані. Відповідну перевірку, згідно з вимогами застосунку, слід виконати перед використанням значень з ненадійних джерел у запитах LINQ, призначенням властивостей сутностей або передачею до інших API EF Core. Це включає будь-які дані, що вводяться користувачем для динамічної побудови запитів. Навіть під час використання LINQ, якщо ви приймаєте дані, що вводяться користувачем, для побудови виразів, вам потрібно переконатися, що можна створювати лише цільові вирази.
