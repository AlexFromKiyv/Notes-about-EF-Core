# Пагінація

Пагінація означає отримання результатів сторінками, а не всіма одразу; зазвичай це робиться для великих наборів результатів, де відображається інтерфейс користувача, який дозволяє користувачеві переходити до наступної або попередньої сторінки результатів.

Попередження

Незалежно від використаного методу пагінації, завжди переконайтеся, що ваше впорядкування повністю унікальне. Наприклад, якщо результати впорядковані лише за датою, але може бути кілька результатів з однаковою датою, то результати можуть бути пропущені під час пагінації, оскільки вони впорядковані по-різному в двох запитах на пагінацію. Упорядкування за датою та ідентифікатором (або будь-якою іншою унікальною властивістю чи комбінацією властивостей) робить упорядкування повністю унікальним та уникає цієї проблеми. Зверніть увагу, що реляційні бази даних не застосовують жодного впорядкування за замовчуванням, навіть для первинного ключа.

## Зсувна пагінація

Поширений спосіб реалізації пагінації в базах даних – це використання операторів LINQ Skip та Take (OFFSET та LIMIT в SQL). Враховуючи розмір сторінки 10 результатів, третю сторінку можна отримати за допомогою EF Core наступним чином:

```cs
var position = 20;
var nextPage = await context.Posts
    .OrderBy(b => b.PostId)
    .Skip(position)
    .Take(10)
    .ToListAsync();
```
На жаль, хоча цей метод дуже інтуїтивно зрозумілий, він також має деякі серйозні недоліки:

1. База даних все одно повинна обробити перші 20 записів, навіть якщо вони не повертаються до програми; це створює потенційно значне обчислювальне навантаження, яке збільшується зі збільшенням кількості пропущених рядків.
2. Якщо будь-які оновлення відбуваються одночасно, ваша пагінація може призвести до пропуску певних записів або їх відображення двічі. Наприклад, якщо запис видаляється, коли користувач переходить зі сторінки 2 на 3, весь набір результатів «зміщується вгору», і один запис буде пропущено.

## Пагінація набору ключів

Рекомендована альтернатива пагінації на основі зсуву – яку іноді називають пагінацією набору ключів або пагінацією на основі пошуку – полягає у простому використанні речення WHERE для пропуску рядків замість зсуву. Це означає запам'ятовувати відповідні значення з останнього отриманого запису (замість його зміщення) та запитувати наступні рядки після цього рядка. Наприклад, якщо припустити, що останній запис на останній отриманій нами сторінці мав значення ідентифікатора 55, нам просто потрібно зробити наступне:

```cs
var lastId = 55;
var nextPage = await context.Posts
    .OrderBy(b => b.PostId)
    .Where(b => b.PostId > lastId)
    .Take(10)
    .ToListAsync();
```

Якщо припустити, що індекс визначено для PostId, цей запит є дуже ефективним, а також не чутливим до будь-яких одночасних змін, що відбуваються з нижчими значеннями Id.
Розбиття на сторінки за допомогою набору ключів підходить для інтерфейсів розбиття на сторінки, де користувач переміщується вперед і назад, але не підтримує випадковий доступ, де користувач може перейти на будь-яку конкретну сторінку. Довільне нумерування сторінок вимагає використання зміщеної пагінації, як пояснено вище; Через недоліки зміщеної пагінації, ретельно подумайте, чи дійсно потрібна пагінація з довільним доступом для вашого випадку використання, чи достатньо навігації по наступній/попередній сторінці. Якщо необхідна пагінація з довільним доступом, надійна реалізація може використовувати пагінацію набору ключів під час переходу на наступну/попередню сторінку та навігацію зі зміщенням під час переходу на будь-яку іншу сторінку.

## Кілька ключів пагінації

Під час використання пагінації набору ключів часто необхідно впорядковувати за кількома властивостями. Наприклад, наступний запит розбиває сторінки за датою та ідентифікатором:

```cs
var lastDate = new DateTime(2020, 1, 1);
var lastId = 55;
var nextPage = await context.Posts
    .OrderBy(b => b.Date)
    .ThenBy(b => b.PostId)
    .Where(b => b.Date > lastDate || (b.Date == lastDate && b.PostId > lastId))
    .Take(10)
    .ToListAsync();
```
Це гарантує, що наступна сторінка продовжуватиметься саме там, де закінчилася попередня. У міру додавання нових ключів упорядкування можна додавати додаткові речення.

## Індекси

Як і з будь-яким іншим запитом, правильне індексування є життєво важливим для гарної продуктивності: переконайтеся, що у вас є індекси, які відповідають порядку пагінації. Якщо впорядковується за кількома стовпцями, можна визначити індекс для цих кількох стовпців; це називається складеним індексом.
