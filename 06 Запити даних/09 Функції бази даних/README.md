# Функції бази даних

Функції бази даних є еквівалентом методів C# для баз даних. Функцію бази даних можна викликати з нулем або більше параметрами, і вона обчислює результат на основі значень параметрів. Більшість баз даних, які використовують SQL для запитів, підтримують функції бази даних. Тому SQL, згенерований за допомогою трансляції запитів EF Core, також дозволяє викликати функції бази даних. Методи C# не обов'язково повинні строго перетворюватися на функції бази даних в EF Core.

* Метод C# може не мати еквівалентної функції бази даних.
    * Метод String.IsNullOrEmpty перетворюється на перевірку на null та порівняння з порожнім рядком у базі даних, а не на функцію.
    * Метод String.Equals(String, StringComparison) не має еквівалента в базі даних, оскільки порівняння рядків не може бути легко представлене або імітовано в базі даних.
* Функція бази даних може не мати еквівалентного методу в C#. Оператор ?? у C#, який не має жодного методу, перетворюється на функцію COALESCE в базі даних.

## Типи функцій бази даних

Генерація SQL в EF Core підтримує підмножину функцій, які можна використовувати в базах даних. Це обмеження пов'язане з можливістю представлення запиту в LINQ для заданої функції бази даних. Крім того, кожна база даних має різну підтримку функцій бази даних, тому EF Core надає загальну підмножину. Постачальник баз даних може вільно розширювати генерацію SQL в EF Core для підтримки більшої кількості шаблонів. Нижче наведено типи функцій баз даних, які підтримує та однозначно ідентифікує EF Core. Ці терміни також допомагають зрозуміти, які переклади вбудовані в постачальників EF Core.

## Вбудовані та користувацькі функції

Вбудовані функції постачаються з попередім визначеням у базі даних, але користувацькі функції явно визначаються користувачем у базі даних. Коли EF Core перетворює запити для використання функцій бази даних, він використовує вбудовані функції, щоб переконатися, що функція завжди доступна в базі даних. Розрізнення вбудованих функцій необхідне в деяких базах даних для правильної генерації SQL. Наприклад, SqlServer вимагає, щоб кожна визначена користувачем функція викликалася з іменем, пов'язаним зі схемою. Але вбудовані функції в SqlServer не мають схеми. PostgreSQL визначає вбудовані функції у публічній схемі, але їх можна викликати з іменами, пов'язаними зі схемою.

## Агрегатні, скалярні та табличні функції

* Скалярні функції приймають скалярні значення, такі як цілі числа або рядки, як параметри та повертають скалярне значення як результат. Скалярні функції можна використовувати будь-де в SQL, де можна передати скалярне значення.
* Агрегатні функції приймають потік скалярних значень як параметри та повертають скалярне значення як результат. Агрегатні функції застосовуються до всього набору результатів запиту або до групи значень, згенерованих застосуванням оператора GROUP BY.
* Табличні функції приймають скалярні значення як параметр(и) та повертають потік рядків як результат. Табличні функції використовуються як джерело таблиці в реченні FROM.

## Ніладичні функції

Ніладичні функції – це спеціальні функції бази даних, які не мають параметрів і повинні викликатися без дужок. Вони схожі на доступ до властивостей/полів екземпляра в C#. Ніладичні функції відрізняються від функцій без параметрів тим, що останні вимагають порожніх дужок. Немає спеціальної назви для функцій бази даних, які завжди вимагають дужок. Іншою підмножиною функцій бази даних, що базується на кількості параметрів, є варіативні функції. Варіативні функції можуть приймати різну кількість параметрів під час виклику.

## Зіставлення функцій бази даних в EF Core

EF Core підтримує три різні способи зіставлення між функціями C# та функціями бази даних.

### Вбудоване зіставлення функцій

За замовчуванням постачальники EF Core надають зіставлення для різних вбудованих функцій через примітивні типи.
For example, String.ToLower() translates to LOWER in SqlServer. Ця функціональність дозволяє користувачам безперешкодно писати запити в LINQ. Зазвичай ми надаємо переклад у базі даних, який дає той самий результат, що й функція C# на стороні клієнта. Іноді, щоб досягти цього, фактичний переклад може бути чимось складнішим, ніж функція бази даних. У деяких сценаріях ми також надаємо найбільш доречний переклад, а не збігаємо семантику C#. Ця ж функція також використовується для забезпечення загальних перекладів для деяких доступів до членів C#. Наприклад, String.Length перекладається як LEN у SqlServer. Окрім постачальників, автори плагінів також можуть додавати додаткові переклади. Ця розширюваність корисна, коли плагіни додають підтримку для більшої кількості типів як примітивних типів і хочуть перекладати методи поверх них.

### Відображення EF.Functions

Оскільки не всі функції бази даних мають еквівалентні функції C#, постачальники EF Core мають спеціальні методи C# для виклику певних функцій бази даних. Ці методи визначено як методи розширення над EF.Functions для використання в запитах LINQ. Ці методи залежать від постачальника, оскільки вони тісно пов'язані з певними функціями бази даних. Отже, метод, який працює для одного постачальника, ймовірно, не працюватиме для жодного іншого. Крім того, оскільки метою цих методів є виклик функції бази даних у перекладеному запиті, спроба їх оцінки на клієнті призводить до винятку.

### Зіставлення функцій, визначених користувачем

Окрім зіставлень, що надаються постачальниками EF Core, користувачі також можуть визначати власні зіставлення. Користувацьке зіставлення розширює переклад запиту відповідно до потреб користувача. Ця функціональність корисна, коли в базі даних є користувацькі функції, які користувач хоче викликати зі свого LINQ-запиту.
